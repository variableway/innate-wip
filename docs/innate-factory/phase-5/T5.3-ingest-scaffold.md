# T5.3 收编 scaffold：innate new app / plugin / skill

> Sprint: Phase 5（W1）· 状态: 未开始 · 规模: L · 前置: T5.1 · T5.2（registry 读写层）

## 目标

`innate new app` 移植 new_app.py 全流程（golden 对照）；`innate new plugin --track package|iframe` 与 `innate new skill` 是**新能力**，随两份新模板（plugin-package / skill）一起交付——总方案 §1 目录树里最后两块模板拼图（app-tool / desktop-shell 仍不做，等需求）。

## 背景与动机

收编 app 生成 = Go 版与 python 版行为锁死（Phase 4 已验证的流程是唯一真源）。plugin/skill 是新命令：双轨方案（plugin-dual-track.md）定了 package-as-plugin 的契约形态，总方案 §8 定了 skill 模板格式，本卡把它们变成可 `innate new` 出来的实体。

## 工作项

1. **`innate new app`**：逐步骤移植 T4.2–T4.7（instantiate / git / registry / build / deploy / remote）。golden 测试：同参数下 `innate new app X` 与 `python3 new_app.py X` 产物树 diff 为零（node_modules 与 .git 排除）。
2. **新模板 `factory/templates/plugin-package/`**（双轨方案 §1 的落地件，固化方法论复用 T3.2 三列清单）：

   ```
   plugin-package/
   ├── TEMPLATE.yaml
   ├── package.json          # name {{plugin-id}}、exports map、"innate-plugin": true、peerDeps react/@innate/ui
   ├── src/
   │   ├── index.ts          # export const plugin: InnatePlugin（manifest/data/pages 三件契约）
   │   ├── data.ts
   │   └── pages/
   └── README.md             # 宿主接入：workspace 依赖 + registry import + 一行式路由包装
   ```
   占位符规范沿用 T3.4 集合，增 `{{plugin-id}}`。
3. **`innate new plugin <id> --track package`**：复制模板 → 替换 → 默认生成进**核心仓** `packages/plugin-{{plugin-id}}`（`--in-app <name>` 生成进指定 app）→ registry/plugins.yaml 登记（`track: package, source: "@innate/plugin-{{id}}"` 或 workspace 名）。
4. **`innate new plugin <id> --track iframe`**：不生成代码，仅登记 plugins.yaml（`track: iframe, src: <URL 参数>`）——双轨方案：iframe 轨"只登记不生成"。
5. **新模板 `factory/templates/skill/`**：SKILL.md 脚手架（frontmatter + 触发描述 + references/ 约定，对齐 skill-creator 格式，总方案 §8）。**`innate new skill <name> [--app X]`**：生成 → 登记 registry/skills.yaml（level: repo 且带 app；无 --app 生成到 `base/wip-skills/` level: user）。
6. 冒烟 CI 矩阵扩为 `[app-content, plugin-package, skill]`（T3.9 预留的动态发现此刻可启用）。

## 产物

`innate new app|plugin|skill` + 两份新模板 + plugins.yaml/skills.yaml 登记通道 + 冒烟矩阵扩展。

## 验收标准

- [ ] golden：Go 与 python 生成树 diff 为零（含占位符零残留断言）
- [ ] package 轨：生成的插件包被核心仓 workspace 引用后 build 绿（betterstack-guides 是现成参照物）
- [ ] iframe 轨：仅 registry 条目变化，零代码生成
- [ ] skill：生成后 `registry/skills.yaml` 条目正确；repo 级与 user 级落位都对
- [ ] 冒烟 CI 三模板全绿

## 风险与注意

- plugin-package 的"一行式路由包装"要宿主配合（app 路由文件 re-export）——模板 README 写清手工步骤即可，**不做自动改宿主路由**（改别人的 app/ 目录是高风险动作，v1 不碰）。
- golden 测试对时间敏感字段（README 生成日期等）要归一化，避免每日假红。

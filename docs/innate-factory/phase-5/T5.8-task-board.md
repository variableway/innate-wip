# T5.8 innate task import / board + making 看板视图

> Sprint: Phase 5（W4）· 状态: 未开始 · 规模: M · 前置: T5.1
> 设计依据：总方案 §7、[task-docs-workflow.md](../../solution/task-docs-workflow.md)

## 目标

任务包 ↔ GitHub Issues 双向打通（`innate task import` / `board`），网站 making 模块升级为看板视图。做完后：板（状态）、context pack（上下文）、网站（展示）三层各就各位，T5.7 的 dispatch 有板可依。

## 背景与动机

§7.1 选型：GitHub Issues + Projects 是唯一零新设施、agent 友好（gh CLI）、网站友好（sync 链已存在）、PR 联动的选项。现状盘点：wip 已有 `task/project/_template/` 与 `task/issues/_template.md`（任务包结构）、`packages/task-watcher`（data→网站同步环，已运行）、making 模块 issues 渲染（已存在）、`submit-tasks-to-issues.js`（手工提交脚本雏形）。缺的是：批量 import 的规范性、状态模型定稿、看板列视图。

**状态模型定稿（本卡的首要决策，T5.7 依赖它）**：单一真源 = **issue label**（`backlog` / `in-progress` / `in-review`），GitHub Projects 列只是视图同步；理由：label 是 gh CLI 与 query 都最稳的接口，Projects 列的 API 操作重且易漂移。定稿后回填总方案 §7 一行。

## 工作项

1. **`innate task import <pkg>`**：读 `task/project/<pkg>/`（handoff/spec/context）+ `task/issues/T*.md` → 逐条 `gh issue create`：title 取任务卡标题、body 链回仓内文件、label = `backlog` + 任务包名；输出 issue 号回写 `task/issues/T*.md` 头部（`issue: #N`）——下次 import 幂等跳过。取代 `submit-tasks-to-issues.js`（其退役随 T5.2 python 退役一批处理）。
2. **`innate task board`**：按 label 聚合输出四列（Backlog / In-Progress / In-Review / Done），含 assignee（agent 身份，§7.3 第 3 条）；`--watch` 可选（轮询刷新）。
3. **网站看板视图**（making 模块升级）：
   - 数据链复用：task-watcher sync 已产 `data/issues.json`；扩展字段：labels（状态列）、assignees（agent 身份）
   - making/issues 页升级列布局（四列横向 kanban），无 JS 依赖的纯 SSG 形态（与 static export 兼容）
4. ** Projects 联动（轻做）**：`gh project` 把 issue 加进 Project 视图（可选步骤，失败不阻塞——真源是 label）。
5. docs/innate-factory 任务卡与 issue 的关系收口：本 sprint 文档体系的任务卡（T*.md）就是 import 的输入形态之一，`innate task import` 支持直接吃本目录格式。

## 产物

`innate task import` / `board` + making 看板视图 + 状态模型定稿（回填总方案 §7）。

## 验收标准

- [ ] import 一个真实任务包：issues 建好、label 正确、body 链回文件、幂等重跑零新建
- [ ] board 输出四列且 agent 身份可见；与 GitHub 网页状态一致
- [ ] 网站看板视图：sync 后列与身份正确渲染，static build 兼容
- [ ] 状态模型定稿文字回填总方案 §7（label 为真源，Projects 为视图）

## 风险与注意

- `data/issues.json` 的字段扩展要向后兼容（现有 making/issues 渲染不能破）——新字段可选、旧渲染无感。
- `gh issue create` 限流：批量 import 加节流与断点续传（幂等性就是续传机制）。
- 不要把 board 做成第二个"自建看板"——终端输出够用就走，重交互是 GitHub Projects 网页的事，CLI 只保证状态可见。

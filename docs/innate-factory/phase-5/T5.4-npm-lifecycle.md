# T5.4 innate npm start / stop / publish（verdaccio 生命周期）

> Sprint: Phase 5（W2）· 状态: 未开始 · 规模: M · 前置: Phase 2（verdaccio 已 selfhost 化）
> 对应里程碑 M3，即 [tasks/innate-cli.md](../../../../../../tasks/innate-cli.md) 的原始需求

## 目标

`innate npm start|stop|publish|status` 一组命令接管 verdaccio 全生命周期与 `@innate/*` 发布：从"手工 docker compose + 手工 pnpm publish"变成一条命令，且下游 app 的拉包体验零变化。

## 背景与动机

tasks/innate-cli.md 原始需求（原文要点）：本地私有 npm 仓不需要权限或只要简单认证；运行 pnpm dev 类脚本前能一键启停 verdaccio；通过 cli 控制从私有仓拉包与发包。Phase 2 已把 verdaccio 落进 `base/innate-selfhost`（compose + `.npmrc` scope 路由），本卡把操作面收进 CLI。已有素材：`base/innate-backend/scripts/npm-registry.sh` 与 `skills/npm-registry`（吸收其逻辑，之后由 CLI 取代脚本入口）。

## 工作项

1. `innate npm start` / `stop`：包装 Phase 2 的 compose 文件（`docker compose -f base/innate-selfhost/... up -d verdaccio` 形态）；`status`：容器存活 + `/-/ping` + 已登录身份。
2. `innate npm publish`（在包目录执行）：
   - 自动识别目标：当前目录是包（有 package.json 且 name 属 `@innate` scope）；或 `--package base/innate-fe-base/packages/ui` 显式指定
   - 前置：verdaccio 未起则自动 `start`（可 `--no-auto-start` 禁用）
   - 执行 `pnpm publish --registry <url>`（无认证或简单 token 认证，按 Phase 2 的 verdaccio 配置）
   - 版本纪律（总方案 §9 第 4 条）：changesets + semver 从第一天执行，本地 verdaccio 不豁免——publish 前检查有版本变更，拒绝同版本重发静默覆盖语义
3. 认证信息：若 Phase 2 配了 token，存 workspace 级 `.innate/`（gitignore）而非全局 `~/.npmrc`——避免污染机器全局 npm 配置。
4. 文档：`innate npm --help` 即是操作手册（start/stop/publish/status 四节，含 fe-base 发 ui 的完整示例）。
5. **可选扩展（不进 DoD）**：`innate dev link/unlink`——消费仓依赖临时改写 `link:` 零发布联调（§9 开发回环），显式可见防忘记切回。

## 产物

`innate npm` 四命令 + `.innate/` 认证位 + help 文档。

## 验收标准

- [ ] 冷机全链：`innate npm start` → fe-base 目录 `innate npm publish` → 任一 app `pnpm install` 拉到新版本——全程无手工 docker/pnpm-registry 参数
- [ ] `stop` 后 `status` 如实报告；publish 自动拉起服务
- [ ] 同版本重发被拒；升版后发布成功
- [ ] 全局 `~/.npmrc` 未被修改（污染检查）

## 风险与注意

- `pnpm publish` 与 `npm publish` 的行为差异（workspace 包默认防误发，需 `--no-git-checks` 或走 `pnpm -r publish`）——以 fe-base 实测为准，help 里写明用哪个。
- 不要在 CLI 里管 verdaccio 的数据备份/迁移——那是 selfhost 层（innate-selfhost/scripts 的 backup.sh 体系）的职责，CLI 只管生命周期。

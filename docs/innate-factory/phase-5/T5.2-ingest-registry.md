# T5.2 收编 registry scan / clone

> Sprint: Phase 5（W1）· 状态: 未开始 · 规模: M · 前置: T5.1

## 目标

把 `scripts/scan-innate-apps.py` 与 `scripts/clone-innate.py` 的语义完整移植为 `innate registry scan` / `innate registry clone`，以 byte 级对照测试证明零漂移，然后让 python 版进入 deprecated 过渡期。

## 背景与动机

总方案 §4（M2：收编现有 python 脚本）。scan 的语义是 factory 的宪法级机制（目录为源），移植漂移 = 事实源损坏。python 版语义要点（scan.py 头部注释，2026-09 核实）：

- 递归扫 `innate-apps` + `base`（默认深度 3），**目录是 git repo 且有 origin remote 才记录**；SSH URL 归一化为 https
- repo 可嵌套（repo 里独立 clone 的 repo 也记录）；同 repo 多路径只保注册路径
- 合并：path 匹配保 name/desc 刷 repo；URL 匹配视为搬移自动改 path；都不匹配默认删除（`--keep-missing` 保留）；`--regenerate` 全量重建不保留
- **EXTRA_KEYS**（kind / template / templateVersion / deploy 等手工字段）read→merge→write 往返保留

## 工作项

1. Go 实现 `innate registry scan [--depth N] [--keep-missing] [--regenerate]`：语义逐条对齐上述规则，YAML 输出格式与 python 版 byte 级一致（缩进 / 分组注释 / 字段顺序）。
2. Go 实现 `innate registry clone`（读 registry/apps.yaml，逐条 clone 到 path，已存在跳过；对齐 clone-innate.py 行为）。
3. **对照测试**（收编卡的核心验收形态）：

   ```
   同一真实 workspace 树 → python scan 输出 vs innate registry scan 输出 → diff 必须为零
   附带 --keep-missing / --regenerate / 嵌套 repo / URL 搬移四个场景用例
   ```
4. CI 接线：factory CI（总方案 §1：registry 一致性检查）加一步 `innate registry scan && git diff --exit-code registry/`——registry 与磁盘永远一致。
5. python 退役：两脚本头部加 deprecated 注释指向 `innate registry`，保留一个版本周期后删除（删除是显式的后续动作，不静默消失）。

## 产物

`innate registry scan/clone` + 对照测试 + CI 一致性步 + python deprecated 标记。

## 验收标准

- [ ] 真实 workspace 上两种实现输出 byte 级一致（含 EXTRA_KEYS 往返）
- [ ] 四个场景用例（keep-missing / regenerate / 嵌套 / 搬移）行为一致
- [ ] clone 幂等：重复执行零变化
- [ ] CI 一致性步在故意的 registry 手改（模拟漂移）时变红
- [ ] python 脚本带 deprecated 标记且 README 指引迁移

## 风险与注意

- byte 级一致意味着连注释分组（`# === content ===`）都要复刻——如果觉得"注释不该锁死"，那是重构 YAML 生成器的冲动，**忍住**：先零漂移收编，格式演进是另一个显式决定。
- scan.py 同时服务根 `registry.yaml`（外部 skills 仓，SCAN_DIRS 不同）——本卡只收编 innate 这份（apps.yaml）；`registry.yaml` 的去留按总方案 §10 留到 W3 评估。

# T5.6 innate skill link（用户级 skill 软链）

> Sprint: Phase 5（W3）· 状态: 未开始 · 规模: S · 前置: T5.1
> 对应总方案 §8"factory 动作"

## 目标

`innate skill link --agent zcode|claude|opencode…` 把用户级 skill（`base/wip-skills/`）软链进各 harness 的用户级 skill 目录，并维护 `registry/skills.yaml` 的 `linked` 字段。跨项目的通用知识一次安装、处处发现。

## 背景与动机

总方案 §8 三层 skill 里的**用户级**层：`base/wip-skills/` → 软链 `~/.agents/skills/` 等。参照 arkcli-connect 同款模式（把能力同步进本机所有 AI agent）。仓库级 skill 随 app 模板走（Phase 3 T3.6 已解决）、任务级随 dispatch prompt pack 走（T5.7），用户级缺的就是本卡的 link 通道。

## 工作项

1. `innate skill link --agent <harness>`：
   - 目标目录映射表：zcode → `~/.zcode/skills/`（或其实际发现路径，实现时以 zcode-configuration-guide 为准）、claude → `~/.claude/skills/`、opencode → `~/.opencode/skills/`，映射外置配置可扩展
   - 遍历 `base/wip-skills/` 下每个 skill 目录，逐个 `ln -s`（已存在同名链接：指向相同则跳过，不同则报冲突不覆盖）
2. `registry/skills.yaml`：user 级条目维护 `linked: [zcode, claude]` 字段；unlink 时移除。
3. `innate skill list`：本机视角——哪些 skill、链进了哪些 harness、断链检测（目标被删）。
4. `innate skill unlink --agent <harness>` / `--all`。
5. `wip-skills` 里**非 skill 目录**（docs / tasks 等杂物，2026-09 目录盘点可见）的过滤：只链含 `SKILL.md` 的目录。

## 产物

`innate skill link/unlink/list` + skills.yaml 维护 + harness 目录映射配置。

## 验收标准

- [ ] link 后 zcode 与 claude 两个 harness 都能发现并触发一个测试 skill（真实对话验证，不是只看文件存在）
- [ ] skills.yaml 的 linked 字段与实际软链一致（双向核对）
- [ ] 重复 link 幂等；断链被 `list` 检出
- [ ] 非 skill 目录零误链

## 风险与注意

- 各 harness 的 skill 发现路径有版本漂移风险（升级后目录变了）——映射表外置配置 + `list` 的断链检测就是为此设计的，doctor（T5.5）的 skills.yaml 检查项再加一条"link 指向的 SKILL.md 仍存在"。
- 软链跨机器不可移植：link 是**本机动作**不进 git（registry 记状态，链本身每台机器自己建），README 写明新机器初始化 = clone workspace + `innate skill link --all`。

# T3.6 AGENTS.md + starter skill 内置

> Sprint: Phase 3 · 状态: 未开始 · 规模: M · 前置: T3.4

## 目标

模板自带 AGENTS.md 与仓库级 starter skill（`.agents/skills/{{app-name}}-dev/`），让任何 harness（Claude Code / ZCode / OpenCode / DeepSeek 系）进入生成的 app 即知道怎么干活——"生成即可用"对 agent 同样成立。

## 背景与动机

总方案 §8：SKILL.md 是跨 harness 事实标准，**仓库级 skill 是 app 的一部分**——随模板生成、随 app 版本化、零安装自动发现。wip 自身目前没有 AGENTS.md 与 `.agents/skills/`（2026-09-09 核实），这两件是模板新增；fe-base 的 AGENTS.md 可作风格参照。

## 工作项

1. 模板根 `AGENTS.md`，内容骨架：
   - 项目一句话 + 目录导览（apps/web、packages、data、content）
   - dev / build / verify 命令表（含 `build:static` 与 `GITHUB_PAGES` 形态）
   - static export 约束（`output: 'export'`、`dist/`、无服务端运行时、basePath 规则）
   - 数据管道约定（sync 脚本怎么跑，按 T3.2 决策项 B 的最小示例写）
   - plugin registry 规则（怎么加插件、双轨边界、指向 skill 的 references/plugin-registry.md）
2. `.agents/skills/{{app-name}}-dev/SKILL.md`，skill-creator 对齐格式：
   - frontmatter：name: `{{app-name}}-dev` + 一句触发描述（"在本仓开发/构建/排障时使用"）
   - 正文：精简版工作指引，细节下沉 references/，按需加载
3. `references/` 四件（总方案 §8 规定的 starter skill 最小内容集）：

   | 文件 | 内容 |
   |------|------|
   | `commands.md` | dev / build / verify / 数据同步命令全集与常见排查 |
   | `static-export.md` | 约束与坑：无 SSR API、动态路由要 `generateStaticParams`、basePath/assetPrefix |
   | `data-pipeline.md` | data/ 目录契约、sync 脚本、sync-state 语义 |
   | `plugin-registry.md` | SitePlugin manifest、双轨决策规则（一句话版：承载内容→package；工具且外部/不可信→iframe）、注册步骤 |
4. 注意 skill 目录名含 `{{app-name}}` 占位符，纳入 T3.4 的 rename 规则；冒烟 CI 断言实例化后 skill 目录名正确。
5. 可选回流（不属本卡验收）：把同款 AGENTS.md + `.agents/skills/innate-wip-dev/` 补回 wip 仓，验证"模板反哺出身源"通道。

## 产物

模板内 `AGENTS.md` + `.agents/skills/{{app-name}}-dev/`（SKILL.md + references/ ×4）。

## 验收标准

- [ ] SKILL.md 有 frontmatter（name/description）且触发描述可被 harness 索引
- [ ] 四件 references 覆盖总方案 §8 规定的四个必选主题
- [ ] 实例化后 skill 目录名 = `<app-name>-dev`，内容中零占位符残留
- [ ] AGENTS.md 所有命令在实例化副本里逐条可执行（抄命令即能跑）

## 风险与注意

- skill 内容要**克制**：写约束与命令，不写营销话术；过长会稀释触发可靠性（skill-creator 的经验）。
- references 里的命令引用了 `--filter` 包名（`{{app-name}}-web`），与 T3.2 决策项 A 联动——A 若改判，本卡命令同步改。

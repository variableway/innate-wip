# T3.3 模板主体固化

> Sprint: Phase 3 · 状态: 未开始 · 规模: L · 前置: T3.2（清单终稿）

## 目标

按 T3.2 清单机械执行，产出 `factory/templates/app-content/`：骨架完整、个人数据删净、（暂带 wip 原名硬编码值）能裸 build。占位符化是下一步（T3.4），本卡先把"删得对不对"验证掉。

## 背景与动机

固化分两步走可以各自验收：本卡回答"骨架完整吗、删干净了吗"，T3.4 回答"参数化对吗"。混在一起出问题时无法定位是删错了还是替换错了。

## 工作项

1. 建分支 `factory/template-app-content`（innate-workspace 仓）。
2. 按清单**保留列**复制骨架到 `factory/templates/app-content/`；**删除列**一律不复制；preset 候选条目单独记录到 `factory/presets/README.md` 的候选清单（不复制文件）。
3. 个人信息 grep 校验（第二道闸），模板目录内以下命中必须为零（白名单：指向 innate-workspace / factory 自身的文档链接）：

   ```
   grep -rn -i -E "innate-wip|variableway|<个人 gh 用户名>|<个人域名>" factory/templates/app-content/
   ```

   注意 `next.config.mjs` 的 fallback `'innate-wip'` 硬编码——本卡先临时改为中性值（如 `'app'`），正式占位符化在 T3.4。
4. 确认零携带物：无 `.git`、无 `pnpm-lock.yaml`、无 `node_modules/`、无 `dist/`、无 `*.tsbuildinfo`、无 `.env*`。
5. **裸 build 首次点亮**（此步允许手工，不是最终验收口径）：

   ```bash
   cp -r factory/templates/app-content /tmp/app-content-trial
   cd /tmp/app-content-trial && pnpm install && pnpm build   # verdaccio 需在跑（Phase 2）
   ```

   构建绿说明骨架自洽；红了回 T3.2 修清单，不在本卡修骨架（保持"清单是唯一事实"的纪律）。

## 产物

`factory/templates/app-content/`（带 wip 硬编码值、可裸 build 的骨架）。

## 验收标准

- [ ] 模板目录树与 T3.2 保留列一一对应，无多余条目
- [ ] 个人信息 grep 零命中（白名单除外）
- [ ] 零携带物清单核验通过
- [ ] `/tmp` 试验副本 `pnpm install && pnpm build` 绿

## 风险与注意

- 最大坑是"顺手修骨架"：固化过程中发现 wip 骨架本身有毛病（如 unused import、坏链接），**回 wip 修好再重新固化**，不要在模板里单边修——否则模板与出身源立即分叉（§9 双向同步从第一天就破）。
- wip 的 `pnpm-workspace.yaml` 引用 `packages/*`，删掉三个包后 workspace 空目录合法，但 `pnpm -r build` 行为要实测（空 packages 不应报错）。

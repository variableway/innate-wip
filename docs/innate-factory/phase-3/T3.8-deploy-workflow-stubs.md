# T3.8 deploy workflow 桩

> Sprint: Phase 3 · 状态: 未开始 · 规模: S · 前置: T3.4

## 目标

模板自带 deploy-pages 与 deploy-cloudflare 两个参数化 workflow 桩。Phase 4 生成器按 `--deploy` 参数启用其一、删除另一个，实现"代码单元 ≠ 部署单元"的登记处落到 CI 层。

## 背景与动机

wip 已有可工作的 `deploy-pages.yml` / `deploy-cloudflare.yml`（生产验证过的逻辑）。模板桩 = 这两件的参数化快照。`fetch-issues.yml` / `full-deploy.yml` 是 making 专属（T3.2 已判删除，随 preset 候选）。

## 工作项

1. 固化 `deploy-pages.yml` 桩：
   - 仓库名 / basePath 相关处占位符化（`{{app-name}}` / `{{base-path}}`）
   - 构建命令对齐模板（`build:static` + `GITHUB_PAGES=true` 形态）
   - 触发分支按模板默认（`main`）
2. 固化 `deploy-cloudflare.yml` 桩：
   - project name 占位符化（默认 `{{app-name}}`）
   - 需要手工配置处（Cloudflare 项目创建、API token secret 名）打 `TODO(innate-factory)` 注释，生成器在 summary 里复述这些手工步骤
3. 两桩都放在模板 `.github/workflows/` 下，**默认保持可运行状态**（占位符替换后即有效），"删哪个"由生成器决定（T4.7），模板本身不做禁用标记。
4. 用 `actionlint`（或等效）在本地校验两桩语法。

## 产物

模板 `.github/workflows/{deploy-pages,deploy-cloudflare}.yml`。

## 验收标准

- [ ] 两桩通过 actionlint 语法校验
- [ ] 手工实例化 + `--deploy pages` 模拟（删 cloudflare 桩）后，workflow 文件内零占位符残留、零 wip 硬编码
- [ ] pages 桩的 basePath 与 T3.4 的 `{{base-path}}` 语义一致（同一变量，不分家）

## 风险与注意

- GitHub Pages 部署对"仓库名即 basePath"有隐含假设（wip 用 `GITHUB_REPOSITORY` 派生），模板桩要显式用 `{{base-path}}` 而不是依赖运行时 env——生成时定死，部署时零猜测。
- cloudflare 桩不要内置任何 token 样例值；secret 名用占位符，泄露样例 = 安全事故。

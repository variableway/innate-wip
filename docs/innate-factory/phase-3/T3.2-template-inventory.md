# T3.2 固化清单：从 innate-wip 三列盘点

> Sprint: Phase 3 · 状态: 未开始 · 规模: M · 前置: T3.1
> 本卡是**活文档**：终稿即固化合同，T3.3 只照单执行。

## 目标

产出 app-content 模板的权威**三列清单**：innate-wip 每个顶层 / 关键条目都有"保留 / 删除 / 改写"判词 + 理由。这是防"固化夹带个人信息"的第一道闸（总方案 §10 风险表原文：不能靠"大概删干净了"）。

## 背景与动机

模板 = wip 成熟模式的快照（§9），但 wip 里同时住着：通用骨架（值得固化）、个人内容与数据（必须删除）、making 等专项模块（应剥离为 preset 候选）。固化前不盘点清楚，删漏泄私、删过缺件。

**盘点输入（2026-09-09 已核实的 wip 现状）**：

- 根：`package.json`（name: `innate`）、`pnpm-workspace.yaml`（apps/* + packages/*）、`tsconfig.json`、`scripts/`（3 件全是 betterstack 专属）、`task/`（个人任务记录）、`docs/solution`（决策文档）、`assets/`、`.local-workflow.state.json`
- `packages/`：`ui`（Phase 2 已撤）、`tsconfig`（基建）、`betterstack-guides`（个人插件）、`task-watcher`（making 数据同步环，已运行）
- `apps/web/`：`app/` 路由 = awesome / betterstack-guides / cheatsheets / collections / feed / making / writing + 首页与 rss；`lib/` 与路由同构分域 + `lib/plugins/`；`content/`（awesome / cheatsheets / writing 个人内容）；`data/`（issues / projects / weekly 等 making 数据）；`scripts/`（fetch-*.js 数据管道 8 件）
- `next.config.mjs`：`output: 'export'`、`distDir: 'dist'`、basePath 从 `GITHUB_REPOSITORY` 派生但 **fallback `'innate-wip'` 硬编码**
- `lib/site-features.ts`：content / feed = true；making / cheatsheets / betterstackGuides / awesome = false
- `.github/workflows/`：deploy-cloudflare / deploy-pages / fetch-issues / full-deploy
- wip 根**当前没有** AGENTS.md 与 `.agents/skills/`——模板的这两件是新增（T3.6），fe-base 的 AGENTS.md 可作风格参照

## 工作项

1. 逐条目落三列判词（下表为**初稿**，逐项核实后可改判）：

   | 条目 | 判词 | 说明 |
   |------|------|------|
   | 根 package.json / pnpm-workspace.yaml / tsconfig.json | 改写 | 骨架保留，name/description 占位符化（T3.4） |
   | `apps/web` 的 app/{layout,page,globals.css,writing,collections,feed} + 对应 lib/ | 保留 | content-basic 内核 |
   | `apps/web/app/{making,cheatsheets,awesome,betterstack-guides}` + 对应 lib/ | 删除 | 非内核模块；making 全家进 preset 候选，其余不带走 |
   | `apps/web/content/*`、`apps/web/data/*` | 删除 | 个人内容与数据；模板留目录 + README 说明放法 |
   | `apps/web/scripts/fetch-*.js` 数据管道 | **决策项 B** | 见下 |
   | `packages/tsconfig` | 保留 | 基建 |
   | `packages/{ui,betterstack-guides,task-watcher}` | 删除 | ui 已被 Phase 2 收敛；后两者为个人/专项件 |
   | 根 `scripts/`（betterstack 3 件） | 删除 | 专属 |
   | `task/`、`docs/`、`assets/`、`.local-workflow.state.json` | 删除 | 个人仓专属；模板自带新 README |
   | `.github/workflows/{deploy-pages,deploy-cloudflare}.yml` | 改写 | 参数化为桩（T3.8） |
   | `.github/workflows/{fetch-issues,full-deploy}.yml` | 删除 | making 专属，随 preset 候选 |
   | `.git` 历史、`pnpm-lock.yaml`、node_modules / dist / *.tsbuildinfo | 删除 | 模板零历史零锁（锁在实例化后生成） |

2. 拍板三个决策项：
   - **A. apps/web 包名**：`@innate/web` → 建议 `{{app-name}}-web`。避免跨 app 同名（pnpm store / 锁文件视角），代价是模板里 `--filter @innate/web` 引用全部占位符化（机械替换，T3.4 覆盖）。
   - **B. 数据管道**：模板保留一个最小 sync 示例脚本（验证"生成即可用"含数据环）vs 整体剥离进 preset。**建议保留一个**（如精简版 fetch 写入 `data/` 的示例），starter skill 的"数据管道约定"一节才有实体可指。
   - **C. feed / collections**：进 content-basic 内核还是最小化。**建议保留**（content-first 站的基本盘，site-features 现状即 content/feed=true）。
3. 密钥与环境变量扫描：`.env*`、token、`gh auth` 引用、个人 URL 逐个判死刑。
4. 本表定稿（状态行改"已完成"），T3.3 以此为唯一输入。

## 风险与注意

- 删过狠 → 模板裸 build 缺件，由 T3.9 冒烟 CI 兜底回补。
- 删不净 → 个人信息进模板，T3.3 的 grep 校验清单是第二道闸。
- making 全家（making 路由 + task-watcher + fetch-issues/weekly/insights/projects/agents + fetch-issues.yml + full-deploy.yml）将来若做 `content+making` preset，此处判词直接复用——清单按"preset 候选"标注而非纯"删除"，给回流留门。

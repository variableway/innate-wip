# T3.7 .npmrc + @innate/ui 接线

> Sprint: Phase 3 · 状态: 未开始 · 规模: S · 前置: Phase 2（硬依赖）· T3.3

## 目标

模板的 `@innate/ui` 依赖与 `.npmrc` 指向 verdaccio 私有源——生成的每个 app 落地即连通设计系统，这是总方案 §9"消费分型"里卫星仓 / 模板产物那一型。

## 背景与动机

Phase 2 完成后：fe-base 是 ui 唯一源，发布到 verdaccio（本机 `http://localhost:4873`）；wip 已撤本地副本改依赖 verdaccio 版本。模板必须继承同一形态，否则生成的新 app 一出生就回到"本地副本分叉"的旧病。

wip 现状（Phase 2 后的目标形态）：`apps/web/package.json` 的 `"@innate/ui": "^0.1.1"`（semver，非 `workspace:*`）；`next.config.mjs` 的 `transpilePackages: ['@innate/ui']`。

## 工作项

1. 模板根 `.npmrc`：

   ```ini
   @innate:registry=http://localhost:4873/
   ```

   默认本机 verdaccio；registry 地址**不做占位符**（v1 只有本机一个源），Phase 4 生成器提供 `--registry-url` 参数改写。
2. `apps/web/package.json`：`"@innate/ui": "^<Phase 2 首发版本>"`，固化时以 verdaccio 上实际最新版为准。
3. `transpilePackages: ['@innate/ui']` 保留（next.config 已有）。
4. 在模板 README 写一段"ui 从哪来 / 怎么升级 / verdaccio 没起会怎样"（三行内）。
5. 为 `--in-core` 生成（Phase 4 预留）记录分支规则：核心仓生成时依赖改回 `workspace:*` 并删 `.npmrc`——规则写在 T3.4 占位符规范与 T4.2 任务卡，本卡只保证默认（卫星仓）形态正确。

## 产物

模板 `.npmrc` + 依赖声明 + README 说明段。

## 验收标准

- [ ] verdaccio 运行中，模板实例化副本 `pnpm install`：`@innate/ui` 解析自 `localhost:4873`（安装日志 / lock 文件源字段可见）
- [ ] build 绿
- [ ] 停掉 verdaccio 再 install：报错信息可理解（pnpm 直报 registry 不可达即可，README 已有提示）

## 风险与注意

- 版本漂移：模板里 pin 的 `^0.1.x` 与 verdaccio 实际版本的落差由冒烟 CI 兜底（T3.9 每次从 fe-base 现发最新），不会长期哑失败。
- `.npmrc` 属于"文本替换白名单"外的特殊文件：Phase 4 引擎若做占位符替换，`.npmrc` 里没有占位符，纯拷贝即可——别把 `@innate:` 当成占位符误伤。

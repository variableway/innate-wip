# T4.6 构建验证内置（"生成即可用"闸门）

> Sprint: Phase 4 · 状态: 未开始 · 规模: S · 前置: T4.2 · Phase 2（verdaccio）

## 目标

生成流程的最后实质步骤：在生成目录内跑 `pnpm install && pnpm build`，绿了才算生成成功。总方案 §5 第 3 条——"构建不绿的模板不允许发布新版本"——在生成侧的镜像：**生成不绿的 app 不算生成成功**。

## 背景与动机

"生成即可用"是 factory 的验收哲学（§3 第 6 步：首次构建必须绿）。如果验证外置（靠人记得去 build），第一个忘记 build 的 app 就带着隐疾上路。内置 = 不可绕过（除非显式 `--skip-build`，仅供调试）。

## 工作项

1. 前置探测：`curl -sf <registry-url>/-/ping` 探 verdaccio；不可达 → 直接失败，报错文案："verdaccio 未运行。先启动：`docker compose up -d verdaccio`（base/innate-selfhost，Phase 2 产物）"。
2. 在生成目录执行 `pnpm install && pnpm build`（subprocess，实时透传输出；超时上限 10 分钟）。
3. 结果处理：
   - 绿：记录耗时进 summary
   - 红：退出非零；保留现场目录（不清理），打印"现场保留在 <path>，日志最后 30 行如下"；提示常见三类原因（verdaccio 版本漂移 / 模板损坏 / 网络）
4. `--skip-build` 逃生阀：仅供模板调试，summary 醒目标注"跳过构建验证，本生成未验证可用性"。

## 产物

`new_app.py` 的 `build_verify` 步骤。

## 验收标准

- [ ] verdaccio 正常：install + build 全绿，耗时入 summary
- [ ] 停 verdaccio 后生成：报错含启动指引，退出非零，现场保留
- [ ] 模拟构建失败（临时改模板引入语法错）：非零退出 + 日志截取 + 现场保留
- [ ] `--skip-build` 有醒目标注

## 风险与注意

- 10 分钟超时对冷缓存 install 偏紧的话调到 15——宁可慢等，不要把慢当失败。
- 这一步同时是模板质量的**持续哨兵**：本地每次生成都隐性复检模板；如果出现"冒烟 CI 绿但本地生成红"，先查环境差（node/pnpm 版本），环境矩阵记录进 T4.8 验收文档。
